## 日常流程（新扫描跑完后）

LTspice 每跑完一次，直接：

```bash
cd scripts
python archive_run.py     # 先归档：波形/网表/日志整个搬进 ../runs_archive/（幂等）
python ingest.py          # 自动找最新的完整日志 → 抓取入库
python build_xlsx.py      # 更新 Excel
python verify_xlsx.py     # 重算 + 逐格校验（可选，但建议）
```

**`archive_run.py` 放在第一步**：它会把这次运行的 `.log/.net/.raw/.op.raw/.db/.asc` 整体归档，
其中 `.raw` 默认是**移动**（工程根目录不再保留，LTspice 下次运行会重新生成）。换扫描参数前跑一次，
就再也不会出现扫描 B 那种"波形被下一次运行覆盖"的损失。细节见 `../runs_archive/README.md`。

`ingest.py` 会自动完成：

1. **自动挑选**工程目录里最新的日志（也可 `python ingest.py <路径>` 指定）；
2. **判断是否跑完**：四个 `.meas` 段齐全、行数等于 `.step` 行数、且文件静置 20 s 以上
   （没跑完就拒绝入库并提示）；
3. **校验**：step↔measurement 配对（用 `VBONE/IBONE` 反算 RB）、`PASS == (IERR<=1)`、
   组合无重复无缺失；
4. **快照原始日志**到 `work/logs/`，把解析结果存到 `work/sweeps/`，登记进 `work/manifest.json`；
5. 若该扫描**已入库**（按"实际跑过的 (VBP,IREF,RB) 集合"的签名判定），会逐位比对并刷新，
   **不会产生重复行**；
6. 重建 `work/parsed_combined.json`（所有扫描的并集）。

之后 `build_xlsx.py` 会自动把新扫描纳入：`Raw_Data` 增加 `Sweep`/`Source_Log` 列标注来源、
README 页自动列出每次扫描、图表自动扩展到新数据范围——**无需改代码**。

`python ingest.py --list` 可查看当前已入库的扫描清单。

### 为什么不用你管文件名

日志里的 `.step` 行是**每次运行的展开值**（几千行），真正的 `.step` 指令只存在于 `.net` 里。
所以入库身份用的是"这次实际跑了哪些 (VBP, IREF, RB)"的签名，与文件名无关；
每次抓取还会把原始日志**快照**下来，因此后续同名日志被覆盖也不影响已入库的数据。

## 判据阈值（可配置）

PASS 是 `IERR` 的纯函数，而 IERR 已按全精度存库，所以**改阈值不需要重跑任何仿真**。

| 位置 | 作用 |
|---|---|
| `scripts/config.py` → `IERR_MAX_PCT` | 决定 `refine.py` 的边界定位与写入工作簿的阈值 |
| 工作簿 `Rmax_Summary` 的「PASS 判据 IERR ≤ (%)」单元格 | `Raw_Data` 的 PASS 列是引用该格的活公式，改这一格全表重算 |

**当前阈值 ±1.5%。** 注意 LTspice 网表里的 `.meas PASS` 仍是 1% 判据（保留作为 IERR
解析正确性的校验），因此 `Raw_Data` 的 PASS 列与日志自身的 PASS 可能不同——工作簿 README
页 §4 已写明。改阈值的动作：改 `config.py` → `ingest.py` → `refine.py`（重新收敛边界）
→ `build_xlsx.py` → `verify_xlsx.py`。

## 精细化扫描（refine.py）

粗扫把每个临界值定位到当时扫描的分辨率（低阻段 1 kΩ、高阻段 10 kΩ）。`refine.py` 自动把它
收敛到工程可用的精度：

```bash
cd scripts
python refine.py                  # 目标：每个窗口 <= 10 Ω（默认）
python refine.py --target 1       # 更细：1 Ω（本次已跑到这一级）
python refine.py --parallel 6 --points 11 --max-rounds 6
```

每一轮它做四件事：

1. 从已入库数据算出每个 (VBP,IREF) 的 `lastPASS`/`firstFAIL` 窗口；
2. 对窗口仍大于目标的组合，**自动改 RB 区间与步长**（11 点等分窗口）并生成一个 deck；
3. 并行调用 `LTspice.exe -b` 跑完，解析日志、校验后**入库**（每轮成为 manifest 里的一条扫描记录）；
4. 重新定位窗口，继续下一轮，直到全部收敛。

实测：24 个临界窗口 × 11 点 = 264 组，**约 10 秒**跑完一轮。

**结论：24/24 收敛到 1 Ω**（相对约 100 kΩ 即 0.001%）。且每个 `lastPASS` 处的 IERR 都在
0.99%~1.00%，说明收敛到的正是 ±1% 阈值的真实交点。

### 踩过的两个坑（写在这里避免重复）

- **LTspice 26 不接受单值 `.step`**：`.step param IREF list 20u` 会报
  "This results in only one step" 并以退出码 1 终止、不产生任何输出。
  精细化 deck 因此把 IREF/VBP 用 `.param` 固定，**只对 RB 做 `.step`**。
- 这些 deck 的日志里只有 `.step rb=<值>`，没有三参数形式，所以 `refine.py` 用专门的
  解析路径（step 顺序 = RB 顺序），不能直接套用整扫的解析器。

## ⚠ 关于日志被覆盖（已有对策）

三次扫描都从同一个 `../Draft2_sweep.asc` 运行，因此**每次运行都会覆盖**上一轮的
`Draft2_sweep.log/.raw/.net`。

- 扫描 B 的原始日志与波形数据（398 MB `.raw`）**已被扫描 C 覆盖，无法找回**；
  仅剩解析后的 2430 组数据（`work/sweeps/` 内）作为记录。这是唯一一次损失。
- 扫描 A 与 C 的原始日志**已快照**到 `work/logs/`（`ingest.py` 对每次入库的扫描自动做）。
- **扫描 A 与 C 的完整运行（含 926.7 MB / 428.1 MB 波形）现已归档**到
  `../runs_archive/`，不再受根目录覆盖影响。

**现在的机制**：`python scripts/archive_run.py` 把工程根目录里所有尚未归档的运行整个搬进
`../runs_archive/<时间戳>_<名字>_<签名>/`（日志、网表、原理图、工作点、`.db`、`.raw` 波形 +
`meta.json` 含每个文件的 sha256）。按"名字 + 日志 sha256"判重，**幂等**，重复执行无副作用；
未跑完的扫描（同一套完整性判据）会被拒绝归档。**换扫描参数前跑一次即可。**

归档时还会顺带核对一件本工程反复踩到的事：**旁边的 `.asc` 往往不是产生这份日志的那一版**
（LTspice 改指令不存盘时，`.asc` 留在旧版本而 `.net` 已是新的）。脚本会把 `.asc` 的指令与
`.net` 逐条比对，把结论写进 `meta.json`，并在能找到真正匹配的原理图时一并归档。
已归档的两次运行的结论都是"同名 `.asc` 不匹配"——**要复现某次运行，以归档里的 `.net` 为准。**

`refine.py` 生成的精细化 deck 不需要额外归档：它们本来就在 `refine/decks_<时间戳>/` 里每轮一个独立文件夹。

**判据 ±1.5%：30/30 组合全部测得真实临界值，且全部收敛到 1 Ω 窗口。**

|---|---|---|---|---|---|
| 3.3 | 317.808 | 164.462 | 63.982 | 30.489 | 13.742 |
| 5 | 490.087 | 250.755 | 98.499 | 47.748 | 22.371 |
| 8 | 794.129 | 403.038 | 159.413 | 78.205 | 37.600 |
| 10 | 996.836 | 504.560 | 200.022 | 98.509 | 47.752 |
| 12 | 1199.551 | 606.083 | 240.631 | 118.814 | 57.904 |
| 15 | 1503.637 | 758.366 | 301.545 | 149.271 | 73.133 |

单位 kΩ，每个值的窗口为 1 Ω（约 0.001%）。

**收敛自检**：每个 `lastPASS` 处的 IERR 都落在 **1.4990%~1.5000%**、`firstFAIL` 处
1.5000%~1.5050% —— 说明 1 Ω 网格正好咬住 ±1.5% 的真实交点，不是数值噪声。

**推荐设计公式**：`Rmax ≈ VBP / ((1 − T/100) × IREF) − R10`（T = 阈值 %，R10 = 3 kΩ）

- 目标电流 **≥20 µA**：平均偏差仅 **0.015%~0.031%**，可直接用于设计
- **10 µA：该式失效**（平均 2.15%、最大 4.28%）—— 其低负载基础误差已达 1.30%，
  距 1.5% 只剩约 0.2% 余量，拐点几乎与顺从电压拐点重合，一阶模型不成立；此情形请直接用表中实测值
- 公式来历：边界处电流已跌落约 T%，负载可用电压由这个已跌落的电流决定，故 R = V/I
  比用 IREF 算大约 T%（1% 判据下该式把偏差从 0.985% 降到 0.063%）

## 需要注意的已知限制

- 临界值已在 1 Ω 窗口内收敛；**非临界区域仍是原始粗分辨率**（1 kΩ / 10 kΩ / 100 kΩ 分段），
  这是有意的——只有临界窗口需要精细定位。
- 10 µA 的 1.5% 判据余量极小（0.198%），其临界值对电路参数变化最敏感；
  若电路改动（如运放失调变化），10 µA 行会最先变化。
- 全程未对缺失点插值或补数；图表只连接真实仿真点。
- 本机 Excel 实测**不支持 MAXIFS/MINIFS**，公式已改用 `LOOKUP` / `SUMPRODUCT` 兼容写法。
- 扫描 B/C 由恢复的 `../Draft2_sweep.asc` 运行产生；该原理图为**重建版**（网表已验证等价），
